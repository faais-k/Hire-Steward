# JobPilot — Risk Register

**Reviewed:** 2026-10-28  
**Status:** Initial audit register updated after Foundation 1; the compensation backend slice exists, while the broader product remains unimplemented.
**Scale:** Severity is qualitative (Critical/High/Medium/Low), not a quantified probability estimate.

| ID | Severity | Risk and evidence | Current controls | Required response / owner decision |
|---|---|---|---|---|
| K-01 | **High** | Root Git is initialized on unborn `main` with a configured remote, but there is no commit baseline. Read-only `git ls-remote` succeeded and advertised no `HEAD` or branch heads. An incomplete ignore policy could stage the nested repositories, conversation export, secrets or generated files. | `.gitignore` rules were inspected; `git check-ignore -v` confirms `reference-repos/`, `Chatgpt-chat/`, the duplicate docs archive and generated/local paths are ignored. | Review the staged initial baseline before the first commit. Do not commit or push until the staged content is presented for review. Use a normal first push; do not force-push or rewrite history. |
| K-02 | **High** | Only the compensation-preference backend slice exists. There is no frontend, Compose service, CI, source/job/application workflow, or full product. | Requirements traceability and memory distinguish the verified slice from remaining work. | Continue the foundation incrementally; do not claim product features complete from specifications or the narrow slice. |
| K-03 | **High** | Job-source permission and permitted methods are not established. Official API docs show technical endpoints but do not grant blanket third-party aggregation or submission authority. Application POSTs for Greenhouse and Lever require employer-issued credentials. | Source registry/capability states and disabled-by-default policy are specified. | Keep all sources disabled until current terms, method, employer configuration, auth, rates and allowed operations are reviewed. Start with fixture/manual mode if review is incomplete. |
| K-04 | **High** | Compensation may be misclassified if public reports, stale facts, unsupported annualization/FX, or future paths bypass the deterministic evaluator. No submitted-application history model exists. | Public API observations are explicitly `UNVERIFIED`, review-required, and never submission-eligible; strict schema rejects caller/model trust claims. Threshold snapshots and the unpaid rule remain deterministic. Only trusted domain inputs can be evaluated for threshold outcomes, and no production verifier currently supplies them. | Build and review a permitted source-ingestion/verifier with immutable provenance before any trusted compensation assessment. Verify PostgreSQL behavior, then route matching, dashboard, schedules, preparation and final gates through the same evaluator. Keep submission disabled until all gates and history are tested. |
| K-05 | **High** | Loopback trusted-host and same-origin checks now protect the current compensation write routes, but this is not authentication or a complete DNS-rebinding defense. Future local routes could omit the guard. | ADR-0008 records current Host/Origin behavior; no permissive CORS is enabled; remote exposure is out of scope. | Apply a consistent reviewed local request-protection policy to future state-changing routes. Do not bind publicly; add auth/TLS/network controls before any remote mode. |
| K-06 | **High** | Candidate resumes, identity, legal/work authorization and application answers are sensitive. No storage encryption, secret-vault, retention, logging/redaction, or data-sharing controls are implemented. Gemini free and paid tiers currently differ on content use (official docs checked 2026-10-28). | Conservative privacy classes and no secret prompt/log rules are specified. | Select secret storage and file/database protection before real personal data. Verify exact provider/model/tier terms at activation and require scoped user consent for candidate-data sharing. |
| K-07 | **High** | A timeout after a remote application/email side effect can lead to duplicates if retried without reconciliation. No state machine or durable executor exists. | ADR-0003 and safety policy specify `CONFIRMATION_UNKNOWN`, evidence, and reconcile-before-retry. | Implement durable attempts, transactional locks, fault-injection simulation and source-specific evidence before any live side effect. Keep live submission disabled. |
| K-08 | **High** | Model-generated matching/answers may hallucinate or treat hostile job/document text as instructions. No evidence store, typed schema, deterministic policy engine or evaluation corpus exists. | AI boundaries and adversarial evaluation are specified. | Add provenance-backed facts, structured outputs, schema validation and backend hard gates before AI drafting; test mandatory mismatch, confidence and unsupported-claim failures. |
| K-09 | **High** | JobSpy explicitly documents proxy use to bypass blocking; its implementation rotates proxies and impersonates Chrome, conflicting with JobPilot's no-evasion policy. Other references also show live automation and unsafe defaults. | Read-only audit; no code copied. | Do not adopt proxy rotation, stealth, fingerprint or CAPTCHA-bypass behavior. Independently review every future adapter against current provider/site rules. |
| K-10 | **High** | `dossier` is AGPL-3.0-only, while most other reference repositories are MIT. Code adoption without notice/compliance/legal review could impose obligations or provenance uncertainty. | No code incorporated. | Require explicit legal review before using/adapting Dossier code; retain notices for permissive MIT portions and audit transitive assets/dependencies before any other reuse. |
| K-11 | **Medium** | Job relevance thresholds, weights and retrieval choices are uncalibrated. No labeled candidate/job set exists; scores could create false confidence. | Docs call scores provisional and keep confidence separate. | Build a labeled set and evaluate baseline keyword/FTS/semantic/hybrid retrieval. Never use scores as an eligibility override or hiring probability. |
| K-12 | **Medium** | Salary annualization can be wrong when hours, duration, commission/stipend basis or currency conversion are unclear. Reference JobSpy uses floats and fixed conversion factors. | Rules require exact decimal arithmetic, provenance and uncertainty states. | Preserve source amount/currency/period and conversion assumptions; require an evidence-backed FX rate; hold ambiguous values for review. Avoid the reference conversion logic. |
| K-13 | **Medium** | Database and filesystem artifacts cannot be committed atomically. A crash can leave orphaned files or DB references to missing files, compromising evidence and restore. | Hashes, manifests and backup/restore are specified conceptually. | Design a staged file-write/commit/reconciliation protocol, integrity checks and clean restore before accepting real documents. |
| K-14 | **Medium** | The task scheduler, job leases, idempotency table, daily counters, day-boundary timezone and recovery behavior are proposed but not selected or implemented. | Database-backed work is the proposed default; no queue initially. | Define transaction boundaries and lock semantics; test concurrent caps, source checkpoints and restart/recovery. Add a broker only if measured backlog/throughput warrants it. |
| K-15 | **Medium** | The project targets Python 3.12+ and Foundation 1 was tested on 3.12.10, but PostgreSQL availability and database-driver behavior are unverified. The Docker engine is unavailable. | Root `pyproject.toml` and `uv.lock` resolve the backend dependencies. SQLite migration/API tests pass. | Run PostgreSQL migration/locking integration against a dedicated DB when available. Pin exact container/runtime images when Compose is introduced; do not infer DB availability from the `psql` client. |
| K-16 | **Medium** | Root Python package/lock ownership is resolved; frontend and Node/container lock/runtime ownership is not yet established because those components do not exist. | Root `pyproject.toml` and one `uv.lock` are recorded in ADR-0008. | Keep one root Python lock; select a frontend lock and exact Node/container versions only when that work starts. |
| K-17 | **Medium** | Extractor/OCR quality, malicious document handling, language coverage and file-size/resource behavior are not validated. | Specs require source-preserving, non-destructive ingestion. | Choose libraries only after license/security/maintenance review; test synthetic fixtures and quarantine invalid/oversized files. OCR remains optional until proven. |
| K-18 | **Medium** | Source/API behavior and model quotas/privacy change over time. Current account-specific limits are unavailable; free tier does not mean private or zero-cost. | Review-date fields and usage telemetry are specified. | Store source/provider review timestamps; verify exact current docs/account limits on activation; stop/defer on budget or quota exhaustion without key/account rotation. |
| K-19 | **Medium** | Backup/export may preserve sensitive data or omit evidence needed to reconcile historical applications. No restore drill or export exists. | `export-import.md` and runbook define checksums, secret exclusion and staging. | Implement sentinel-secret tests, encrypted backup procedures, clean restore and uncertain-attempt preservation before portability release. |
| K-20 | **Low** | The documentation set contains proposed UI tokens, scoring bands, `k=60`, source candidates, runtime floors and phase descriptions that can be mistaken for validated facts. | Docs label many values provisional. | Keep proposed vs confirmed labels; do not put speculative thresholds into code without versioning/evaluation. |
| K-21 | **Medium** | The selected Psycopg 3 distributions report `LGPL-3.0-only`; packaging/redistribution obligations have not received explicit legal review. | License identifiers are recorded from installed distribution metadata in ADR-0008; no code was copied from references. | Obtain explicit license review before bundling or redistributing the application. Do not treat this register entry as a legal conclusion. |
| K-22 | **High** | The project has no complete trusted compensation source-ingestion or verification path. A stored URL/reference, caller assertion or model output cannot establish source authenticity, retrieval, or support for a salary. Therefore no public assessment can currently pass the compensation gate. | Public assessments fail closed with `EVIDENCE_UNVERIFIED`; legacy rows are migrated to an explicit `UNVERIFIED` state and safe effective API results. | Before integrating source-extracted salary into eligibility, implement a controlled verifier that records permitted access, retrieval/source-version provenance, exact supporting span, normalized verified facts, and verifier method/version/time. Keep every unverified case in review. |

## Risk acceptance rule

No unresolved High risk involving source permission, hard eligibility, consent, secrets, duplicate prevention, or uncertain external outcomes may be waived by a score, model output, successful click or UI-only check. Any live side-effect path remains disabled until its specific release gates and explicit user authorization are satisfied.
